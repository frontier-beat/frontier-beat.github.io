# LaTeX edge cases

How paper summaries break on the page, what the renderer now does about each
case, and which ones need a rule in the summarizer prompt.

Renderer: `react-markdown` + `remark-math` (`singleDollarTextMath: true`) +
`rehype-katex` (`throwOnError: false`, `strict: "ignore"`, `trust: false`),
preceded by `normalizeSummary(text, version)` / `normalizeTitle(title)` in
`src/lib/normalize.js`. Titles use the same inline-math path.

Test data: `src/fixtures/summaries-2024.json` (936 v1 rows from the 2024-08-06
backup) and `src/fixtures/edge-cases.json` (33 hand-written cases, generated by
`scripts/make-edge-cases.mjs`; `valid_v2: true` marks the 19 that follow
contract rules 1-4).

Checks: `npm test` (Node render of every fixture, prints failures) and
`npm run test:e2e` (headless Chromium over the `/?fixtures=1` page, counts
`.katex-error` nodes, unknown-command spans, card overflow and console
errors at 375 px and 1280 px). Last browser run (2026-10-13): valid-v2 edge
cases 0 errors, v1 6/936 rows with errors, no card or page overflow, no
console errors, at both widths.

Survives without any special handling (verified by the edge-case set): `$`
inside code spans, `\$`, `*$x$*` and `**$\mathcal{L}$**`, `snake_case` and
`__init__` in prose, `$a_1$ ... $b_1$` on one line, `$p(x|z)$`, `$a<b>c$`,
math starting with a digit (`$2^n$`), `\{ \}`, nested braces, `cases` and
`aligned` with `\\` row breaks, Unicode Greek in math, display math as the
first line, display math inside an indented list item.

## Rules for the summarizer prompt and validator

These are what the renderer cannot fully repair, or repairs only by guessing.
The validator (`src/summary_format.py`) should reject strings that break them.

- **A. No control characters.** The stored string must not contain TAB, CR,
  form feed or backspace. If the model's output passes through `json.loads`
  or a format string, `\text`, `\right`, `\frac`, `\beta` and `\nabla` lose
  their first letter. Reject any `\t \r \f \b` byte.
- **B. Dollars only.** Never `\(...\)` or `\[...\]`.
- **C. Every piece of TeX is inside `$...$` or a `$$` block,** including a lone
  symbol in prose ("with $\theta$ fixed", not "with \theta fixed").
- **D. Escape `%` as `\%` inside math. Use `&` only inside `aligned` or
  `cases`; elsewhere write `\&` or "and".**
- **E. Inside `\text{...}`: no `_` (write `\_`, or use `\mathrm{lr\_max}`, or
  a hyphen), no math commands, no `$`.** Contract rule 3 currently says
  "underscores inside math are plain `_`, never `\_`"; that needs the
  exception "except inside `\text{}`, where `_` must be `\_`".
- **F. Braces balance in every equation; never cut a summary in the middle
  of an equation.**
- **G. Only commands KaTeX supports; never a macro from the paper's own
  source** (`\ours`, `\method`, `\NAME`, `\pkgfoo`). Unicode Greek inside math
  works, but `\alpha` is preferred.
- **H. No `equation`, `align`, `\label`, `\eqref`, `\tag`.** Multi-line
  display uses `aligned` (already contract rule 3).
- **I. Code identifiers go in backticks** (`` `__init__` ``, `` `max_new_tokens` ``).
  A bare `__init__` is bold in markdown.
- **J. Keep `\text{}` to a word or two inside inline math.** A sentence in
  `\text{}` cannot wrap and scrolls sideways on a phone.
